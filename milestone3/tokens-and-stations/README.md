Tokens and Stations
===================

This is a rough draft of the QR code auth token scheme for stations at a
polling place. It's not integrated into the main EGC codebase yet. The idea is:

1. A voter checks in (method not specified; up to voting authority) and is
   given an ok-to-vote QR auth code.

2. Voter scans ok-to-vote at the submit station (voting booth or scanner) and
   receives a vote-in-progress QR code. This one has an IPFS CID in addition
   to the auth stuff, so it can be used to check on their submitted ballet. Code
   for that not written yet. We may also want to encode the PublicRecordMetadata
   here.

3. Voter scans vote-in-progress at a separate challenge station and casts or
   spoils their ballot. They receive a final i-voted QR code with the
   cast/spoil CID. May want metadata here too.

Each auth code is timestamped and signed by the Ed25519 key of the machine
issuing it (checkin desk, submit station, challenge station). That way it's
ready to incorporate into future on-chain dispute resolution, and could be used
today for manual audits.

Each type of station (Checkin, Submit, Challenge) will be a type of
ElectionNode.  CheckStations can probably just be observers, but Submit +
Challenge stations should be devices.

Other than via the auth QR codes, the stations don't need to communicate. I'll
add a couple new contract operations to register each type of station with its
`VerificationKeyHash` on chain, and they can read that.

Quick test script:

```
$ ./tokens_and_stations.py
```
